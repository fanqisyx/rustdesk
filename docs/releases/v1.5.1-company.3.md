# 公司管理客户端 v1.5.1-company.3

本版交付 Windows x64 可运行 EXE，沿用 company.2 的显式 HTTP、设备权限和分享功能。配套服务端为 v1.1.17-company.3 的 HTTP-Setup.exe。程序和源码的校验值见发布附件 SHA256SUMS。

增加可选的明文 HTTP 公司管理地址。用于只有公网 IP、不能占用 80/443、无需证书的部署；配套服务端 v1.1.17-company.3 的 HTTP-Setup.exe，默认管理端口 TCP 21114，可自定义。账号、设备分组、授权和分享规则不变。

登录／注册时填写 `http://自己的公网IP:21114`，勾选「允许此服务器使用明文 HTTP」。HTTP 会明文传输密码、登录令牌、设备凭据和连接票据，链路上的窃听或篡改可能使账号和设备权限被冒用；界面明确显示此限制。未勾选时仍只允许 HTTPS 和开发回环地址。允许 HTTP 只绑定所选 origin，包括端口，不适用于其他地址；所有公司请求仍不跟随重定向，HTTPS 仍校验证书。

控制端登录成功后保存此地址的 HTTP 选择，用于设备目录、分享和原生连接票据。被控端在系统服务实际读取的 RustDesk2.toml 的现有 `[options]` 段中设置：

```toml
[options]
enterprise-server = 'http://自己的公网IP:21114'
enterprise-http-origin = 'http://自己的公网IP:21114'
enterprise-device-token = 'rd_device_该电脑独立凭据'
```

`enterprise-http-origin` 必须与服务器 origin（协议、主机、端口，无末尾斜线）完全一致。修改后重启 RustDesk 服务；控制端和被控端均须升级。旧版 v1.5.1-company.1 不支持公网 HTTP。

回归范围：仅公司登录 UI、公司请求模块、HTTP 请求中既有的公司分支、单台分享入口、公司登录保存配置、原生 company 授权模块和新增配置键。新增翻译键追加至语言表。未修改 hbbs/hbbr 通信、旧的非公司 HTTP 分支、远控协议或共享子模块。

验证包含 Dart 地址审批与注册／请求、不跟随重定向、原生 origin 审批测试。尚需真实公司环境双机远控验收。

GitHub 目前拒绝运行本仓库的 Actions，因此本版使用本机 Windows C++ 工具链构建，沿用 Windows 发布的 Rust 1.75、Flutter 3.24.5、硬件编码和显存渲染配置。桥接文件复用 company.1 成功构建的 CI 产物；对应 FFI 接口和协议文件未变更，未在本机运行桥接代码生成器。Windows x64 自动发布入口仍为 `.github/workflows/company-windows-release.yml`，本版同时修正其 Rust 工具链版本变量引用。

本机构建检查发现 Opus 默认使用动态 C 运行库；`res/vcpkg/opus/portfile.cmake` 现在在 Windows 静态构建中显式启用 `OPUS_STATIC_RUNTIME`，使音频库遵循客户端的静态运行库配置。此项仅改变 Windows 静态构建的链接方式，其他平台和动态运行库构建沿用既有配置。

置顶窗口和打印组件需要的 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll` 随 EXE 一同解压到程序目录，来源为微软官方 Visual C++ 可再分发文件；目标电脑无需安装开发工具。
